# 검사

게임을 실행하는 데는 npm이 필요하지 않습니다. 개발용 검사를 돌릴 때만 Node.js와 Three.js 패키지가 필요합니다.

```sh
npm install
npm test
```

인터넷 없이 돌리려면 같은 버전(r149)의 라이브러리 파일을 직접 지정합니다.

```sh
THREE_PATH=/절대경로/three.min.js npm test
```

검사는 브라우저 없이 Node.js에서 돌아갑니다. 화면에 실제로 어떻게 보이는지는 확인하지 않으므로, 생김새와 움직임은 브라우저에서 직접 봐야 합니다.

## 검사 내용

### `tests/characters.test.cjs` — 캐릭터와 무리

- 펭귄과 게의 네 단계, 모두 여덟 모델에서 GPU에 담아 둔 관절 동작이 원본 동작의 위치와 일치하는지
- 자세 사이를 이어 붙일 때의 오차가 작은지
- 펭귄 네 단계의 걸음 한 주기 동안 좌우 무게 이동과 발 들기가 보이는지, 발이 얼음을 뚫지 않고 한 발은 늘 땅에 닿아 있는지
- 9↔10, 99↔100, 999↔1,000에서 합체와 분리가 맞는지, 가장 큰 무리와 빈 무리에서도 문제가 없는지
- 그림자를 끄고 켤 때, 그리고 관절 동작을 쓸 수 없는 기기에서 정지 자세로 바뀌는지
- 전투 중 몸을 돌려도 장애물 판정에 쓰는 위치는 그대로인지
- 쓰러지는 캐릭터가 전선까지 달려가 한 번만 부딪히고 튕겨 나가는지, 큰 전투에서도 그 수가 제한되는지

### `tests/combat.test.cjs` — 전투

- 효과가 크기가 정해진 풀 안에서만 나오고, 정해진 박자를 지키며, 다시 시작하면 지워지는지
- 전선이 두 무리 사이 빈틈의 한가운데인지, 효과가 부딪힌 지점에서 터지는지
- 동작 줄이기 설정에서 흔들림·승리 점프·느린 화면이 꺼지는지
- 두 무리가 서로 겹쳐 들어가지 않는지
- 전투가 볼 수 있을 만큼 이어지되 너무 길어지지 않는지
- 프레임 간격이 달라도 인원이 줄어든 결과와 승패가 같은지, 비기거나 졌을 때 승리 연출이 나오지 않는지
- 소리가 소리 끔 설정을 따르고 너무 자주 나지 않는지

### `tests/environment.test.cjs` — 길과 유빙

- 길이 시작부터 결승까지 끊기지 않고, 달리는 구역이 평평한지
- 유빙의 모양이 유지되고, 다시 시작해도 모델을 새로 만들지 않고 다시 쓰는지
- 유빙이 길과 눈사람 받침에서 떨어져 있는지, 움직임이 정해진 범위 안인지, 동작 줄이기 설정에서 멈추는지, 멀리 있으면 숨겨지는지
- 같은 스테이지는 늘 같은 배치가 나오고, 다른 스테이지는 달라지는지
- 서로 다른 스테이지 40개에서 크기 분포, 2~4개씩 모인 무리, 빈 수면, 유빙 사이 간격이 지켜지는지

### `tests/water.test.cjs` — 바다와 거품

- 거품의 외곽선이 유빙과 같은 크기, 방향, 위치를 따르는지
- 바다와 거품이 같은 시계를 쓰고, 동작 줄이기 설정에서 함께 멈추는지
- 스테이지를 여러 번 다시 만들어도 바다를 새로 만들지 않고 다시 쓰는지

## 검사하지 않는 것

- 스테이지 생성 규칙(`js/core.js`의 `genLevel`)과 별 계산에는 자동 검사가 없습니다.
- 지도, 업그레이드, 저장도 자동 검사가 없습니다.
- 실제 기기에서의 속도는 확인하지 않습니다.
